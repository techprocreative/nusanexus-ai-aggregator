# nusanexus-ai-aggregator App Flow Document

## Onboarding and Sign-In/Sign-Up
A new user lands on the public home page by visiting the application URL or finding it through a search engine. The home page showcases the value of the credit-based AI aggregator, with clear invitations to sign up or explore a demo. When the user clicks the sign-up button, they are taken to a registration page powered by Clerk. Here, they can register using their email address and a chosen password, or they may opt to sign up through a supported social login provider such as Google. After entering their details, the user receives an email confirmation link to verify their account. Once the email is confirmed, the new user is automatically signed in and directed to the main dashboard.

On the sign-in page, returning users enter their email and password or select a social login option. If the user forgets their password, they click a "Forgot Password" link on the sign-in form and submit their email address. The system sends a password reset link, allowing the user to set a new password. After resetting their password, they return to the sign-in page and can access their account. At any time, the user can sign out via a link or menu item in the application’s header, which safely ends their session and returns them to the public landing page.

## Main Dashboard or Home Page
Once signed in, the user lands on the main dashboard. At the top of the screen, a header shows the application logo, the user’s current credit balance, and a profile menu. A sidebar on the left provides navigation links labeled Dashboard, Chat, Image Generation, Video Generation, Compare, Purchase Credits, Subscription Plans, and Settings. The dashboard view presents an overview of recent activity, including snapshots of recent AI requests, available credits, and suggested next steps, such as exploring the chat interface or topping up credits. From this page, the user clicks any of the sidebar links to move into the corresponding feature flow.

## Detailed Feature Flows and Page Transitions
When the user selects Purchase Credits, the application displays a list of credit packages. Each package outlines how many credits it contains and the price. The user selects a package and clicks Checkout. A checkout page then renders a Tripay payment form. After entering payment details, the user completes the purchase, triggering a redirect back to a payment success page. Behind the scenes, Tripay sends a webhook to the application’s API, which updates the user’s credit balance in the database and logs the transaction. The success page informs the user that credits have been added and provides a button to return to the dashboard.

In the Chat interface, the user arrives at a prompt input field and model selector. The user types a question or instruction and clicks Send. The frontend calls an API route that first verifies the user has enough credits. If the user lacks credits, the route returns a 402 response, and the UI displays a message with a link to the Purchase Credits page. If the user has sufficient credits, the system deducts the cost from the balance, then proxies the chat request to the selected AI provider. The response is streamed back and displayed in the chat window in real time.

On the Image Generation page, the user sees a form to enter a prompt, choose image dimensions, and select a model provider. Upon submitting, the application follows the same credit check and deduction workflow, then calls the image-generation API. Once the image is ready, it appears on the page with options to download or regenerate. The Video Generation page follows an identical pattern, with fields appropriate for video prompts and settings.

The Compare page offers two side-by-side columns labeled Model A and Model B. The user enters a single prompt, selects two providers or models, and clicks Run Comparison. The system checks credits for both calls, deducts them in sequence, then displays the returned results next to each other for easy analysis.

## Settings and Account Management
Under the Settings link, the user can view and update profile information such as name, email address, and password. A separate section shows subscription details, where the user can upgrade or downgrade their plan. In the billing area, users see past invoices, add or remove payment methods, and manage recurring subscriptions. Another tab allows the user to configure notification preferences, choosing which email or in-app alerts they wish to receive. From any settings page, a back button or the sidebar navigation returns the user to the dashboard or any other feature area.

## Error States and Alternate Paths
If the user enters invalid information during sign-up or sign-in, the application validates the input and displays a clear error message above the form. Network failures trigger a full-screen offline message prompting the user to check their connection. During credit checks, if the user has insufficient funds, the API returns a specific error code. The UI catches this and shows a friendly prompt guiding the user back to the Purchase Credits page. In the event that an AI provider returns an error or fails, the application displays an error banner in the relevant feature with the option to retry the request or contact support. All error messages include suggestions for next steps, ensuring the user can quickly correct mistakes or resume normal use.

## Conclusion and Overall App Journey
A typical user journey begins with discovering the landing page, registering an account, and verifying their email. Upon signing in, they see a dashboard that highlights their credit balance and recent activity. Early interactions often involve purchasing an initial batch of credits via the Purchase Credits page. The user then explores AI features through the Chat, Image Generation, or Video Generation pages, with each request automatically checking and deducting credits. For more advanced comparisons, the Compare page provides side-by-side results. At any time, the user can adjust personal details, manage subscriptions, or view billing history in Settings. Error states throughout the app offer clear recovery paths. Over time, the user routinely returns to the dashboard to track usage, purchase additional credits, and leverage the power of multiple AI providers through a single unified interface.
